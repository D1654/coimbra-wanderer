# 有界批量审修：派出、收回、关闭、接续

用于多章分给子agent、作者要求逐章新上下文，或需要控制并发和处理中断时。普通单句修订不启用整批流程；工具名称、并发上限和可恢复状态以宿主实际说明为准。主编负责共享清单、最终取舍与正式稿写入，agent只写自己的候选和记录。拆章减载不能代替全文阅读，也不能自动证明文学质量。

## 明确工作单元与输入

作者要求一章一新编辑时，每个编辑任务只负责一章；前后章原文可作为必要边界读，不赋予修改邻章的权限。同章补读、纠正自己的候选可继续该上下文；换章使用新agent，不把send_input、resume或改岗名算重新隔离。默认不再委派孙代理，除非本任务明确需要且已纳入并发和输出范围。

每个任务有稳定的任务及尝试编号、准确源稿路径/SHA、章号、必要章纲和边界、专属输出目录、可改范围及结束条件。读完整源章后逐段审修，再完整读自己的候选；截断就缩小读取范围补读。已写与待写、作者知道与角色知道、正文与规划分开。任务包含章题审查或重拟时，按[章题参考](chapter-titles.md)另作真实取舍，不为换题编造剧情；不审题的编辑不另加载。

新编辑还须有可找到、版本确定的方法载荷，取[能力入口](chapter-editor.md)；短任务不等于贫乏能力包。完整主编历史不能代替能力准备。批量收件核实方法是否落到当章，不因SHA和读程通过就宣称子agent写得更好。

重试用新尝试编号和专属目录，旧产物保留所属输入。同章默认只有一个当前编辑尝试；旧尝试确已核实关闭或回收并记为失败、取消或superseded后才能另派替补，不把两个正在运行的editor当作一次单章任务。reader复读不受这项编辑互斥限制。用同一冻结起点并行编辑有助于避免相互覆盖，却不会自动消除跨章依赖；影响后章的改动由主编安排边界阅读或后续重新处理，不能让较早变稿偷偷进入另一岗的旧任务。

## 有界派发，不一次启动全书

取宿主允许和本任务需要的较小并发上限，先派少量单章，逐个收回再补队列。计入所有尚未核实关闭或回收的agent；在宿主明确completed、errored仍占槽时，不因它们进入终态就记作空位。派发失败不臆造agent_id或running状态，也不在库存矛盾时继续扩大队列。

主编持有一份最小运行清单：待办、真实agent_id、输入版本、输出目录、运行/交付/失败/关闭或回收状态、收件和待采用情况。任务终态、交付核收、调度位置回收、工具关闭和正文采用是不同状态。实际工具结果及时落盘，不能只在聊天或恢复表中留“verified”。对任务数、章数及重试数分别计数，不把一次失败替补算作多章完成。

准备、冻结或共享清单写入命令先确认进程最终成功，再派发依赖它的agent；宿主返回session/cell表示仍在运行时，先按对应工具等实际完成，不把命令已启动或等待超时当成准备完成。主编是唯一写者也不允许自己启动多个尚未结束的清单更新进程。若spawn已成功但登记失败，该agent仍真实占槽；暂停新增派发，等待原准备进程、核实际agent_id并修复登记，不重派同任务，也不把登记错误记成子岗失败。尚无真实输入时不填补读程。

等待前先做不重复的本地工作；需要下一份实际结果时再等，避免短间隔反复空轮询。工具返回完成消息后读取实际文件，不仅摘一句“已完成”；主编上下文不必反复加载全部原文和所有报告，按任务索引取全差异、必要场面及未决问题。

## 收件后按宿主回收

确认候选/意见、报告、真实阅读范围、源稿和候选版本能恢复，再按宿主实际支持的方式核实回收；有关闭工具时调用并记录实际返回，无关闭工具但确有终态回收约定时取真实终态和库存证据。有效交付可在主编采用之前回收，不必闲置占槽等整批完结。关闭确认不能靠自己把closed设为true，终态消息也不能自动当作已回收。主编把实际工具结果连同批次、任务、尝试和agent身份封装在独立控制目录，不让子agent替自己生成关闭事件；重放别批或别上下文的收件不能进入当前任务。共享文件系统的目录分工不是权限隔离，控制目录也不是不可伪造的安全凭证；实际工具调用须可查，核验计数不能独自授权继续投放。

文件缺失、SHA错版、任务/尝试编号不符、读程缺段或候选被无记录改动，都不能进入当前采用。旧报告保留原样，迟到结果归回它自己的版本；缺材料先恢复，不因找不到就断言当时未读，也不凭标签继承已审。人工声明只能在实际读后填写。

## 失败与中断

agent失败时保留临时稿、失败事实及实际完成范围，核实关闭或回收，再决定重派；不能拼入只读了章首的稿件。相同原因有限重试后先诊断输入、权限、工具或任务粒度，不无限追加agent。恢复已关闭agent可用于同任务说明或取回依据，不能称全新首读或用它接另一章的编辑。

任务中断时保存准确源稿、候选、收件、关闭凭据、未决项和下一动作。未确认的运行/关闭状态保持未知，先对照工具实际状态与可恢复产物，避免重复派发。复读或另开岗位需要说明为何有收益；不为使新法“胜出”反复测试直到得到喜欢的意见。

## 主编采用与章间阅读

先核候选全差异和正文依据，分开记录收益、损失和保留项。逐段照顾不等于逐段强改；字号、SHA或覆盖表通过不是文学通过。主编统一写正式稿、大纲、人物状态和阅读衍生件，避免agent同时改共享主档。改后阅读记录绑定实际版本，沿用不变范围要注明来源，不把更换哈希冒算新全文首读。

逐章编辑后看相邻章的实际边界：声口、情绪和动作是否接得上，人物知情、物件与伤势是否仍成立，是否多次重复同一种结尾。独立阅读仍走[中性首读](independent-reading.md)，首次意见保存前不看编辑理由。全书题名最后按真实章目连看，必要时回原文；孤立题目好看不代表连成目录不重复。

章题批量作业中途也取真实新目录检查，不把一次单章命名成功扩大成整批稳定。编辑可取小份已形成的题名片段作去重复参照；独立首读仍不取主编的审美解释。哪一章实际用了哪个方法、何时收到后置反馈，另记真实版本，不因批次入口升版给旧候选统一换标签。

## 可选机械核验契约

[batch_revision.py](../scripts/batch_revision.py)只核单章新上下文模式，不生成读程或调度工具。仅用Python标准库，复用同目录的段句索引脚本。

```text
python -X utf8 -B path/to/scripts/batch_revision.py --workspace project-root --registry run/registry.json
```

清单最小形态如下，实际字段使用真实路径及SHA，不把示例当成执行凭据：

```json
{
  "run_id": "review-run",
  "max_open_agents": 2,
  "output_root": "run/units",
  "control_root": "run/control",
  "tasks": [{
    "task_id": "editor-001-a1",
    "attempt_id": "review-run-editor-001-a1",
    "kind": "editor",
    "chapters": [1],
    "source": {"path": "run/inputs/001.md", "sha256": "actual-source-sha256"},
    "work_dir": "run/units/001-a1",
    "status": "queued",
    "closed": false
  }]
}
```

宿主生命周期默认沿用close_agent旧契约；没有该工具时，只有显式声明terminal_inventory能力、引用真实能力依据，并逐项保存规范化终态及库存后才能使用回收模式。closed与slot_released分别记，旧缺口不改写。完整字段、严格类型与不可证明的边界见[宿主生命周期记录](agent-lifecycle.md)；不要自己把工具字段猜成该规范化格式。

实际派发后填agent_id和running。完整交付后returned，delivery指向带SHA的收件JSON，内含run_id、task_id、attempt_id、agent_id、source_sha256以及candidate、report、read_record三个文件条目；reader不要求新的candidate，输入是冻结读稿。read_record含source和candidate各自的`{"source_sha256": "实际值", "ranges": [...]}`，范围采用[逐段参考](close-revision.md)的实际声明契约。核验使用同份字节快照，并检查可写交付不是输入或其他任务产物的硬链接别名；这不是文件锁。

旧close_agent模式关闭后closed为true，close_receipt位于与output_root分离的control_root，其JSON有同一run_id、task_id、attempt_id、agent_id，operation为close_agent，tool_result保存实际返回的`{"previous_status": ...}`。unknown/not_found不能确认回收。failed/cancelled保留失败范围，不能算交付；superseded保留被替代尝试，必须先核实关闭或回收再派替补。合成测试文件只能证明结构校验，不称真实工具证据。

工具返回integrity_only、declarations_only=true、live_inventory_verified=false；计数deliveries_verified仅指文件、版本和全文范围声明相符，不是文学采用数量，也不是程序看见了agent真正理解全文。open_agents是清单声明和绑定关闭或回收事件推算值，必须与主编真实工具库存相符才可派发。工具不能查询宿主真实库存、证明关闭文件未伪造或自动决定题目和正文；真实调用、阅读与取舍仍须另有实际依据。
