# agent 协作

按工作需要选择分工。保持一个对整体创作负责的主写或总编，负责采用版本、人物与情节的状态及最终裁决；这项责任不依赖一个永不结束的会话。

构想未定或重要阶段需要不同判断时，按[独立创作设计](design-collaboration.md)委派故事构想与结构、人物与关系任务，主编统一取舍；不固定每章调用。

资料研究、针对原文的内容核查和独立文学审读有明确范围时，可以委派给独立子 agent。需要减少自评影响时，使用不继承写作讨论的上下文，提供必要原文和作者目标。确需章节或故事单元另行执笔时，按人物与作品记忆参考准备交接。

委派任务说明输入、输出位置、采用版本、允许修改的范围和结束条件。继承当前适用模型配置；不要因角色名称假定模型或文学能力。没有委派工具时可以顺序完成，但要说明审读没有独立上下文。

岗位名称说明责任，不提供虚构履历。需要提高某项能力时，依[岗位准备](preparation.md)给真实材料和练习反馈；恢复时只读与本次工作相关的经验。记录谁实际执笔、谁只审读、谁见过其他意见；同一上下文换角色名不算独立评阅。

新章节编辑通过[能力入口](chapter-editor.md)取得本任务所需的方法；宿主支持显式Skill引用时在派发中使用，否则给准确入口并要求实际读用。派发当前决定、准确原文和必要边界，不默认继承整段主编历史；这不免除项目指令，已预载背景也不能冒称未见。经验、校准和批量调度按实际需要提供，不要求每个编辑读控制器流程。继承模型配置不等于继承Skill或既往阅读。主编以当章真实取舍和完整候选核能力，不以头衔、文件数或模板复述验收；不足时作有原文依据的同章纠正。

同一稿件的独立审读可以并行，评阅者不看对方报告。冻结其输入版本；多个角色不要同时覆盖正文或人物主档。当前环境共享文件系统，分工约定不等于权限隔离。

有前后依赖的章节按可接续状态推进。逐章换写作者、按单元交接或继续原写作者都是选择；没有实际收益依据时，不增加固定角色、辩论轮次和交接。

作者已明确一章一新agent时，按此范围拆分，不以持续执笔的通用建议抵消；同章补读可以保留该上下文，但换章不能用改岗位名或恢复旧agent冒充新上下文。批量作业按[有界批量审修](batch-revision.md)按宿主能力控制未回收数量、落盘收件、关闭或回收核实、失败替补和准确版本；小任务不必启用整批台账。拆小可以减少载荷，不证明旧漏检的原因一定是token占用。

对子 agent 的交付读实际文件并核对目标，不能只凭“完成”消息验收。失败或意见冲突时先查依据、范围和版本；没有新增证据时不要无限增加评审者。
